# BrainDance 社区功能实现说明

## 1. 功能目标

本次实现的目标，是在现有 Flutter App 中加入一个“社区”模块，让用户可以把自己拍摄并生成的记忆模型发布出来，并以两种方式浏览：

1. 流式浏览
   类似短视频或内容流，用户可以纵向下翻查看别人的 3D 记忆。
2. 地图探索
   把带地点的记忆投到世界地图上，用户点击地点后可以查看该地点的内容集合，并进入具体模型。

同时，用户在 `RecallPage` 中浏览自己已有模型时，可以通过长按模型卡片，弹出“分享到社区”的操作入口。

## 2. 本次做了什么

本次改动主要包括以下部分：

### 2.1 新增社区主页面

新增文件：

- `app/lib/pages/community.dart`

该页面被接入主导航，作为新的一级 Tab 页面，包含两个子视图：

1. `流式浏览`
   使用纵向 `PageView` 展示社区贴文。
2. `地图探索`
   使用自绘世界地图背景和地点点位，展示可探索地点。

页面顶部提供“分享记忆”入口，打开发布弹窗。

### 2.2 修改主导航

修改文件：

- `app/lib/main.dart`
- `app/lib/extra_func/language.dart`

具体改动：

1. 在主页面路由切换中加入 `CommunityPage`
2. 在底部悬浮导航条中增加 `community` 页签
3. 为中英文语言包加入 `community` 文案

### 2.3 新增社区发布逻辑

在 `community.dart` 中实现了：

1. `showCommunityComposerSheet(...)`
   统一的社区发布弹窗入口
2. `_CommunityComposerSheet`
   发布表单界面
3. `CommunityComposerResult`
   发布结果数据结构

发布表单支持：

1. 选择已有模型
2. 填写标题
3. 填写描述文案
4. 选择或输入地点名称
5. 输入经纬度

### 2.4 接入 Recall 页面长按分享

修改文件：

- `app/lib/pages/recall.dart`

实现方式：

1. 保留原有点击卡片进入模型查看器的逻辑
2. 去掉卡片底部显式“分享到社区”按钮
3. 为模型卡片新增 `onLongPress`
4. 长按时弹出底部操作菜单
5. 当前菜单提供一个动作：
   - `分享到社区`

这样做的原因是：

1. 不会让 `RecallPage` 卡片区域过于拥挤
2. 日常查看模型仍然是单击，主路径不受影响
3. 分享属于低频操作，更适合长按触发

## 3. 页面和交互结构

### 3.1 社区主页结构

`CommunityPage` 的主体结构如下：

1. 顶部标题区
   说明社区的用途，并提供发布按钮
2. 统计卡片
   展示当前社区记忆数、地点节点数
3. Tab 切换
   - 流式浏览
   - 地图探索
4. 具体内容区

### 3.2 流式浏览

流式浏览使用纵向 `PageView`。

每条社区贴文卡片包含：

1. 封面图
2. 模型名
3. 地点名
4. 标题
5. 描述文案
6. 作者名
7. 发布时间标签
8. 进入记忆按钮
9. 地点内容按钮

其中：

- `进入记忆` 会跳转到 `WebGLViewerPage`
- `地点内容` 会打开该地点的记忆列表弹窗

### 3.3 地图探索

地图探索页包含三层：

1. 地图卡片
   自绘一个简化的世界地图背景
2. 地图点位
   根据经纬度把内容投射到二维地图平面
3. 地点详情区
   显示当前选中地点的主内容
4. 地点横向列表
   方便在移动端直接滑动切换地点

这里没有接入第三方地图 SDK，而是先做了一版轻量可运行的交互原型。这样可以先完成完整产品链路，再决定是否引入地图依赖。

## 4. 数据流和实现方式

### 4.1 社区读取逻辑

`CommunityRepository` 负责社区数据读写。

主要方法：

1. `fetchPosts()`
   读取 `community_posts`
2. `fetchShareableModels()`
   读取当前用户可分享的 `model_assets`
3. `createPost(...)`
   新建社区贴文

### 4.2 社区数据回退策略

为了避免后端表尚未部署时界面完全不可用，本次实现做了回退策略：

1. 优先读 Supabase
2. 如果查询失败或没有数据，则回退到本地 demo 数据
3. 如果发布失败，则把新发布的内容暂存在本地内存列表 `_localDrafts`

这样做的意义是：

1. 方便前端先做页面联调
2. 即使后端尚未完全上线，也能演示完整交互
3. 发布路径和浏览路径不会因为缺表而完全阻塞

### 4.3 模型 URL 处理

社区贴文最终需要跳转到 3D 模型查看器，因此需要把 `model_assets.ply_path` 转成可访问 URL。

这里复用了 Recall 页原来的做法：

1. 模型文件路径通过 Supabase Storage 转公共 URL
2. 如果存在 `point_cloud.*` 文件，则尝试自动推导同路径下的 `webgl_poses.json`
3. 将模型 URL 和 pose URL 一起传给 `WebGLViewerPage`

## 5. Recall 页面长按分享实现

`RecallPage` 中新增了以下逻辑：

### 5.1 新增方法

1. `_showModelActions(model)`
   长按模型卡片后弹出底部菜单
2. `_shareModelToCommunity(model)`
   调用社区发布弹窗并完成发布
3. `_modelToCommunityOption(model)`
   把 Recall 页中的模型对象转换成社区模块需要的 `CommunityModelOption`

### 5.2 交互调整

原先：

- 模型卡片底部直接放一个“分享到社区”按钮

现在：

- 单击卡片：进入模型查看
- 长按卡片：弹出操作菜单
- 菜单中选择“分享到社区”：打开发布弹窗

这样主界面更干净，也更符合“查看”和“操作”的分层。

## 7. 当前限制

这次实现已经完成了“可运行的社区原型”，但仍有一些后续可完善点：

1. 地图并不是真正的地图 SDK
   目前是轻量自绘世界地图，不支持缩放、拖动、卫星图层

2. 社区内容没有做真正的分页
   当前是简单拉取最近内容

3. 地点选择仍然是手动输入经纬度
   还没有接反向地理编码或真实地图选点

4. 发布后的本地回退数据是内存级
   App 重启后不会保留

5. 社区动作菜单目前只有一个动作
   后续可以继续扩展“删除”“重命名”“查看详情”等能力

## 9. 后续建议

如果继续推进社区功能，建议按以下顺序扩展：

1. 接入真实地图组件
   让用户直接在地图上选点，而不是手输经纬度

2. 把社区发布接到录制完成和生成完成流程
   这样用户完成生成后可以一键发布

3. 增加社区贴文详情页
   允许评论、点赞、收藏、举报

4. 增加用户维度内容页
   支持进入某个用户的公开记忆列表

5. 做社区内容分页和缓存
   提升移动端浏览体验

1. 社区主页面
