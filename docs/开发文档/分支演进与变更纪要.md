# BrainDance 分支演进与变更纪要

## 文档目的

本文基于仓库内各主要分支的 Git 提交历史整理，目标不是简单罗列提交，而是总结 BrainDance 在不同研发阶段中的升级路线、工程方法、性能优化路径与具有独创性的技术突破。整体风格参考 changelog，但更强调“为什么变强了”和“工程上是怎么做的”。

## 统计口径

- 主要读取方式：`git log main..branch --reverse --no-merges`
- 对只有合并提交、或明显从其他功能分支继承而来的分支，补充使用 `git log parent..branch`
- `origin/main` 与 `main`、`origin/dev` 与 `dev`、`origin/tianxingleo` 与 `tianxingleo` 指向同一主线时，不重复拆成两份内容
- 某些分支存在重复导入、历史整理、同主题多次提交的情况，本文按“能力演进”去重总结，不机械重复

## 主干分支演进

### `origin/RatherHard-dev`

**分支定位**

早期真正把 BrainDance 从“实验脚本”推向“可运行系统”的主研发分支。它最重要的价值不是某个单点功能，而是首次把 3DGS 预处理、智能分割、SfM 加速、Web 查看器、RAG 检索和工程化重构连成一条链。

**阶段演进**

1. **基础成型期：从脚本堆叠到可用原型**
   - `c8970f0`、`bf91cea`、`7d362d5`：完成基础 PyTorch 后端、坐标转换、本地拍摄类型识别、降噪与自动裁剪。
   - 这说明项目最早就不是单纯做“渲染展示”，而是把采集质量控制前置到输入端。

2. **预处理与数据清洗强化期**
   - `f7fc3ab`、`66463f1`、`6929582`：持续优化 3DGS 预处理流程、图片清洗、COLMAP 路径管理和模型文件管理。
   - 核心升级点是把“跑通”变成“稳定跑通”，尤其强调脏数据治理、路径治理、可恢复性。

3. **AI 分割链快速迭代期**
   - `41f34f6`：把 LLM、环境修正、背景涂黑、词汇树匹配接进 `process_3dgs_cut.py`。
   - `935527e`、`94d8e5a`：加入训练图生成与蒙版质量质检。
   - `4d6b4ef`：针对显存溢出、COLMAP 流程与 AI 分割策略做联合重构。
   - `796f7e7`、`7a0f232`、`d53aa51`：SAM3D 接入、RTX 5070 兼容修复、自动 Mask 生成增强。
   - `8c3c9ea`、`4e9771c`、`97c8d94`、`9a0d892`、`b46464b`：围绕 VGGSfM、蒙版质量、RGBA 透明通道、多目标中心锁定、mask_path 伪影治理做了一整轮精修。

4. **SfM / 稀疏重建加速期**
   - `45f3df4`、`b1ad992`：以 VGGT 替换 COLMAP，提交中直接给出“5 分钟到 5 秒 / 0.5 秒”的级别式提速。
   - `29a0487`：再换到 GLOMAP，在算力和显存要求不变的条件下继续提速约 50%。
   - 这组提交体现出非常明确的工程思路：不是盲目卷模型，而是持续替换瓶颈环节。

5. **可视化与交互表达期**
   - `560a3b2`：基于 Vue3 + Three.js 做最基础 3DGS 渲染器并适配 Flutter WebView。
   - `93b2c76`：重构交互控制器，加入 VR 模式、360°自由视角、HTTPS 自适应。
   - `5fbd045`、`28de90f`、`dbf6cb7`：实现点云到全彩模型的两阶段加载、粒子汇聚飞入/扩散显现、自适应粒子数与尺寸。
   - 这不是普通的“看模型”，而是在做能体现记忆生成过程感的叙事式 Viewer。

6. **RAG 与工程重构期**
   - `6e1d750`：完成 RAG 基础架构，升级 `text-embedding-v4` 并引入场景语境融合。
   - `e239ff8`：加入 RTX50 系 TensorFloat32 加速支持。
   - `ff8df58`：里程碑式工程化重构，引入 `PipelineConfig`、`ImageProcessor`、`ColmapRunner`，消除全局变量与隐式依赖。
   - `b108757`：把点云百分位裁剪做成可配置能力。

**代表性优化点**

- 通过拍摄类型识别、降噪、自动裁剪，把垃圾输入挡在管线入口。
- 用“检测 + 分割”组合、中心物体锁定、蒙版质检、EXIF/透明通道修正来抬高 3DGS 输入质量。
- 多次替换 SfM 后端，从 COLMAP 到 VGGT 再到 GLOMAP，说明团队对瓶颈定位极其敏感。
- Viewer 不是静态渲染器，而是具备成长动画、粒子表达与 XR 探索的交互前台。

**工程方法 / 架构手法**

- 用配置中心替代散乱全局变量。
- 用职责类封装图像处理、重建执行器和主流水线。
- 把性能优化、硬件适配和环境修复写进正式提交，而不是留在本地经验中。

**值得强调的升级与进步**

这个分支奠定了 BrainDance 的方法论底座：先提升输入质量，再替换最慢的核心环节，最后把结果可视化与产品化。它把“实验成功”升级为“有体系地成功”。

### `dev`

**分支定位**

`dev` 是 BrainDance 的中后期综合主干。相对 `origin/RatherHard-dev`，它不再只盯 AI 引擎，而是把 Flutter 产品化、任务队列、Recall 工作流、Dashboard 运维看板、多条 3DGS 流水线统一进一个较成熟的工程体系。

**阶段演进**

1. **前端能力抬升与产品骨架成型**
   - `5b8bef4`、`628633f`、`53bbfd9`、`3c08e17`：多窗口、语言切换、TDesign 风格统一、夜间模式、缓存机制、生成界面与视频缩略图逐步补齐。
   - `6e74e68`、`87c3546`、`82ed204`、`9df0e71`、`4cb0d3b`：相机系统修复、权限治理、插件升级、拍照自动入相册。
   - 这里体现的是“移动端采集链”的工程化稳定，而不是单点 UI 装饰。

2. **云端协同与移动端基础设施完善**
   - `4676825`：加入 Supabase 存储与任务迁移工具。
   - `1c21f9e`、`0647e06`：引入 `supabase_flutter`，打通上传与任务创建调试链。
   - `8af6189`：引入 Riverpod 并配合性能优化。
   - `d0313a5`、`7eeb0ae`：修安全问题、修初始化错误，说明工程链开始进入可持续维护阶段。

3. **任务系统、实时通知与 Recall 工作流成型**
   - `99f0f12`、`8c54719`、`1478196`、`7a1dece`：任务页、通知弹窗、本地缓存、全局状态监听。
   - `34fba0e`、`7278b99`：从轮询切到 Supabase Realtime，并重构全局通知系统。
   - `79ada63`、`0d27b68`、`cf0ad1a`：Processing 日志展示、展开查看、任务页 logs 显示。
   - 这一阶段的升级重点是“用户能感知后台处理进度”，把长耗时 3DGS 任务从黑盒变成透明过程。

4. **3DGS 流水线多样化与环境治理**
   - `805e041`、`1e1c48d`：GPU 选择可配置。
   - `40aad16`、`63f5614`：新增 DA3+SuGaR、DA3+2DGS、Sparse2DGS 流水线。
   - `730f771`、`e41af16`、`479ddbb`、`5997966`：通过子模块引入 SuGaR、2DGS、SAM3D、Depth-Anything-3、Sparse2DGS。
   - `7dc38b6`、`9db0de7`、`215236d`、`d4e779f`、`a32f6d2`：用文档、复现规范和参数修正确保多流水线不是“摆设”。

5. **Dashboard、设计语言与比赛文档重构**
   - `af758a5`、`fc3043b`：新增独立 Supabase 运维看板。
   - `c712208`、`198efd2`、`c606afe`：把控制台视觉改成接近 Flutter App 的设计语言，并清理展示噪音。
   - `2ab9ac3`、`c24f996`、`5bad55a`、`e9b3aaa`、`10c1338`：README、技术报告、创新分析和比赛文档全面重写。

6. **生成、回顾、社区与导航体验升级**
   - `ba24c01`、`681ef75`、`02bac80`、`a40f87b`、`0d65724`：图生、文生、上传跳转、对象/场景提示、图标清理。
   - `80b0e78`、`1630258`：悬浮导航岛、毛玻璃底栏、全局动效资产。
   - `37f59f8`、`8f522ea`、`63251f5`、`ebc4536`：Recall 页面重构、模型交互优化、端侧问答接入。
   - `ed9df22`、`7eb9ef6`：把录制、回顾、生成和社区模块串成统一产品工作流。

**代表性优化点**

- 从轮询切换到 Realtime，显著降低前后端交互延迟感与状态不一致风险。
- 将多流水线能力正式纳入仓库治理，连同子模块、文档、GPU 选择一起标准化。
- 通过日志展开、通知累积、缓存更新时机控制，把长时任务体验做得更“像产品”。

**工程方法 / 架构手法**

- 组件风格统一，说明已经从功能优先转向设计系统优先。
- 使用子模块 + LFS + 复现文档管理复杂第三方依赖。
- 把运维控制台也纳入代码库，形成“开发、处理、监控”一体化工程。

**值得强调的升级与进步**

`dev` 的核心进步是把 BrainDance 从“技术链很强”继续升级为“产品链、运维链、文档链也能支撑持续迭代”的系统。

### `tianxingleo`

**分支定位**

`tianxingleo` 是当前最新整合支线，主要作用是在 `dev` 的基础上继续做查看器交互、Recall/RAG 性能、网页预览与仓库收尾整理。

### `origin/raine_flutter`

**分支定位**

`origin/raine_flutter` 是 Flutter 产品化真正的大主线。它继承了早期移动端搭建工作，又继续扩展任务系统、Recall、日志、上传、导航、社区和端侧问答，后续多个专题分支都从这里分叉。

**阶段演进**

1. **移动端基础设施成型**
   - 从多窗口、设置页、缓存机制、缩略图、相机权限与插件升级，一直到 `1c21f9e` 的 Supabase 初始化，基本把移动端采集与设置系统打牢。

2. **认证 / Viewer / 搜索融合集成**
   - 继承 `tianxingleo-flutter` 的成果，把认证、3D 查看器、语义搜索与主题系统变成稳定产品骨架。

3. **任务列表、通知、日志系统成型**
   - `99f0f12` 到 `cf0ad1a` 这一串提交构成完整的任务可观测性方案。
   - 核心升级包括本地缓存、全局通知、Realtime 订阅、累积计数、渐隐动画、日志展开。

4. **页面收敛与录制链优化**
   - `f035e8d`：合并 Recall 与 Task 页面文件，减少页面碎片化。
   - `c274bd8`、`6d8e840`：录制视频保存到相册、录制期间禁止息屏。

5. **生成与回顾工作流深化**
   - `ba24c01`、`02bac80`、`a40f87b`、`0d65724`：上传后自动跳转、图生、文生、场景提示。
   - `37f59f8`、`ed9df22`、`7eb9ef6`、`1630258`：Recall 重构、设计语言升级、社区模块、悬浮底栏。
   - `7432103` 所在的 Time Peeling 分支也以这里为母线。

**代表性优化点**

- 任务处理体验从“提交后等待”升级为“提交、接收通知、查看日志、回顾内容”的完整闭环。
- 录制端把视频保存、保活、防误操作等细节补齐，体现明显的产品化意识。
- 设计语言不断向统一视觉体系收敛。

**工程方法 / 架构手法**

- 通过 Realtime 代替轮询，降低状态同步复杂度。

## 结论：分支升级主线的真实含义

从整个仓库历史看，BrainDance 的升级不是线性的，而是几条能力线交替抬升：

1. **输入质量线**
   - 从拍摄识别、降噪、自动裁剪，到 YOLO-World + SAM3、蒙版质检、EXIF 清理，目标始终是提升 3DGS 的源数据质量。

2. **计算效率线**
   - 从 COLMAP 到 VGGT 到 GLOMAP，再到 GPU 选择可配置、TF32、抽帧频率调优，本质是在不断替换和压缩瓶颈。

3. **产品体验线**
   - 从基础 Flutter UI，到任务通知、日志透明化、Recall 工作流、社区、端侧问答、毛玻璃导航，说明团队没有停留在技术演示层。

4. **工程方法线**
   - 配置中心、模块化类封装、策略模式、多流水线、子模块治理、LFS、运维看板、完整复现文档，标志着项目已经具备持续工程化能力。

5. **独创能力线**
   - 单图 3DGS、空间语义锚点、语义镜头跳转、快慢双链、Time Peeling，都不是简单“接个开源库”，而是在已有系统上做新的能力组合。

如果用一句话概括这 500+ 次提交体现出的升级方向，那就是：**BrainDance 从“能生成 3DGS 的原型”不断进化为“具备输入治理、算力优化、产品交互、云端协同和新型时空语义能力的完整系统”。**
