# Qwen3 评测快照复现说明（2026-03-24）

## 1. 为什么要补这份说明

这轮新增未见数据 OOD benchmark 和空间 hardcases 都直接依赖远端 Supabase 实时数据。

这在“先看真实效果”阶段是优点，但在“反复复跑对比”阶段会变成问题：

- 远端 `model_assets` 持续新增
- `recent_*` 类题会被更晚数据顶掉
- 同一套 benchmark 在不同时间重跑，结果可能漂移

所以这次已经把评测链路补成了 **retrieval snapshot 可冻结复现** 的版本。

## 2. 新增产物

新增脚本：

- [export_retrieval_snapshot.py](/ltx-data/BrainDance/ai_engine/finetune_qwen3/scripts/export_retrieval_snapshot.py)

它的作用是：

1. 先对 benchmark 题集逐题执行一次真实 retrieval
2. 把完整 retrieval chain 固化到本地 JSON
3. 后续评测脚本可直接复用该快照，不再受数据库继续变化影响

已支持读取 snapshot 的脚本：

- [evaluate_unseen_ood_benchmark.py](/ltx-data/BrainDance/ai_engine/finetune_qwen3/scripts/evaluate_unseen_ood_benchmark.py)
- [evaluate_spatial_hardcases_candidates.py](/ltx-data/BrainDance/ai_engine/finetune_qwen3/scripts/evaluate_spatial_hardcases_candidates.py)

本次已经实际导出的 snapshot：

- `ai_engine/finetune_qwen3/data/braindance_qwen3_unseen_ood_retrieval_snapshot_20260324.json`
- `ai_engine/finetune_qwen3/data/braindance_qwen3_unseen_ood_spatial_hardcases_retrieval_snapshot_20260324.json`

说明：
- 这两份都是本地冻结快照文件，不纳入 Git。

它们都新增了参数：

- `--retrieval_snapshot_file`

## 3. 复现方式

先导出 retrieval snapshot：

```bash
conda run -n qwen3_ft python ai_engine/finetune_qwen3/scripts/export_retrieval_snapshot.py \
  --cases_file ai_engine/finetune_qwen3/data/xxx.json \
  --output_file ai_engine/finetune_qwen3/data/xxx_retrieval_snapshot.json
```

再用 snapshot 重跑 benchmark：

```bash
conda run -n qwen3_ft python ai_engine/finetune_qwen3/scripts/evaluate_unseen_ood_benchmark.py \
  --cases_file ai_engine/finetune_qwen3/data/xxx.json \
  --retrieval_snapshot_file ai_engine/finetune_qwen3/data/xxx_retrieval_snapshot.json
```

```bash
conda run -n qwen3_ft python ai_engine/finetune_qwen3/scripts/evaluate_spatial_hardcases_candidates.py \
  --cases_file ai_engine/finetune_qwen3/data/yyy.json \
  --retrieval_snapshot_file ai_engine/finetune_qwen3/data/yyy_retrieval_snapshot.json
```

## 4. 这次修复解决了什么

现在两套 benchmark 可以同时具备两种口径：

- `live`：继续看真实线上链路效果
- `frozen`：固定 retrieval 证据，只比较下游模型回答

这样以后再做横评时，可以把两个问题拆开：

1. 是不是 retrieval 先漂了
2. 还是模型回答本身退化了

## 6. 这次工作的意义

这一步看起来像工程补丁，但其实非常关键，因为它把今天这轮 benchmark 从：

- “一次性的实验记录”

变成了：

- “可长期复跑、可严格对比、可定位链路回退点的评测资产”
