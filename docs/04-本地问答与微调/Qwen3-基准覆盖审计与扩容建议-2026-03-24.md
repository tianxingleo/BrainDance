## 4. 关于 benchmark 条数：答案是，确实太少

单看“有没有一套 OOD benchmark”，当前答案是有。

但如果看“它够不够支撑多版本稳定横评”，当前答案是还不够：

- `24` 条 unseen OOD
- `10` 条 spatial hardcases

对于定性探索是有价值的，但对于：

- 多版本细粒度横评
- 回归分析
- 新训练轮次优劣判断
- retrieval 与 generation 的稳定拆因

这个量仍然偏小。

更重要的是，当前 `24 + 10` 这套题覆盖到的唯一 `scene_id` 只有 `9` 个，而最近实际已有 `40` 个 scene。

这也是为什么这轮我没有停在“指出太少”这一步，而是直接把扩容包做了出来：

- `24` 条 base unseen OOD
- `112` 条 recent scene 自动扩容候选
- `10` 条 spatial hardcases

合并去重后已经形成一套本地总包：

- 总题数：`146`
- 可打分题数：`102`
- 覆盖唯一 `scene_id`：`37`

## 10. 最终判断

这次审计之后，可以把结论讲得非常明确：

1. 当前 benchmark 条数确实偏少。
2. 最近新增 scene 和 object 确实大量未纳入。
3. 这两个问题现在都已经被推进成了可运行实现：recent scene 扩容包把覆盖率从 `22.5%` 提升到了 `92.5%`，版本矩阵也已经统一落地。
4. 本地版本不是都没跑，但还剩 `7` 个版本没有进入两套老 benchmark，需要后续把它们补进统一矩阵。
5. 运动 / 视频 / 多级重建 pipeline 还停留在测试方案充分、结果横评不足的阶段，但那是独立主线，不应和 Qwen3 QA 微调 benchmark 混做一件事。
6. 高信息密度图表不仅可以做，而且现在已经有了 `plotly` dashboard、静态热力图、版本矩阵 dashboard 三套展示资产。

如果只保留一句最重要的话，那就是：

- 这轮工作已经把“感觉 benchmark 不够”推进成了有数字、有清单、有扩容脚本、有统一版本矩阵、有 dashboard、并且 recent 覆盖率已经实打实抬上去的可执行实现。
