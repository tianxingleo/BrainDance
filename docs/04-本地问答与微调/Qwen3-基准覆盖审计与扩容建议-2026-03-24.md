## 1. 这次审计回答什么

这份审计不是重复已有 benchmark 分数，而是专门回答下面几个更关键的问题：

1. 当前 benchmark 条数是不是太少。
2. 最近新增的那么多场景和物品，是不是其实大部分都还没纳入。
3. 本地这么多微调版本，到底哪些已经跑过、哪些没有统一横评。
4. 运动 / 视频 / 多级重建 pipeline 有没有真正跑完。
5. 图表是不是可以升级成更高信息密度、更直观的可视化。

## 3. 最关键的数字

本次审计的核心数字如下：

- 最近 Supabase 场景数：`40`
- 当前本地 benchmark 覆盖的最近场景数：`9`
- 最近场景覆盖率：`22.5%`
- 当前未见数据 OOD 题数：`24`
- 当前空间 hardcase 题数：`10`
- 当前本地 benchmark 涉及唯一 `scene_id` 数：`9`
- 自动扩容后可新增的本地候选题数：`56`

这意味着一个非常直接的结论：

- 现在这套 benchmark 确实偏小，而且最近新增 scene 大部分还没有被纳入。

## 4. 关于 benchmark 条数：答案是，确实太少

单看“有没有一套 OOD benchmark”，当前答案是有。

但如果看“它够不够支撑多版本稳定横评”，当前答案是还不够：

- `24` 条 unseen OOD
- `10` 条 spatial hardcases

对于定性探索是有价值的，但对于：

- 多版本细粒度横评
- 回归分析
- 新训练轮次优劣判断
- retrieval 与 generation 的稳定拆因

这个量仍然偏小。

更重要的是，当前 `24 + 10` 这套题覆盖到的唯一 `scene_id` 只有 `9` 个，而最近实际已有 `40` 个 scene。

## 5. 关于最近新增场景：大部分确实没算上

这轮审计里，最近 `40` 个场景中，未被当前本地 benchmark 覆盖的有 `31` 个。

也就是说：

- 新增场景里只有少数进入了当前 benchmark。
- 你的直觉“最近新的那么多场景和物品都没算上”是对的。

典型未覆盖的新场景包括：

- `scene_20260323_285206`
  校园乐队动漫插画，含粉发电吉他手、黑短发贝斯手、鼓组、电子琴
- `scene_20260323_969422`
  初音未来夜景、霓虹街道、湿滑斑马线、黄色出租车
- `scene_20260323_074315`
  衣物静物堆叠，牛仔夹克、针织围巾、木地板

这说明当前 benchmark 的问题已经不是“有没有 OOD”，而是：

- OOD 覆盖宽度不够
- 新 scene 纳入速度太慢

## 10. 最终判断

这次审计之后，可以把结论讲得非常明确：

1. 当前 benchmark 条数确实偏少。
2. 最近新增 scene 和 object 确实大量未纳入。
3. 本地版本不是都没跑，但也还没有做到“全谱系统一横评闭环”。
4. 运动 / 视频 / 多级重建 pipeline 还停留在测试方案充分、结果横评不足的阶段。
5. 高信息密度图表不仅可以做，而且现在已经开始有了第一版 `plotly` dashboard。

如果只保留一句最重要的话，那就是：

- 这轮工作已经把“感觉 benchmark 不够”变成了有数字、有清单、有扩容脚本、有 dashboard 的可执行结论。
