# 快慢双链前端对接方案

## 1. 背景与目标

本文档面向 Flutter 前端接入 `video_dual_chain` 快慢双链能力，基于当前仓库代码现状制定，不重新设计计算后端。

当前后端已经具备 V1 快慢双链能力：

- 用户提交一个视频任务，前端只创建一条 `processing_tasks` 记录。
- Python Worker 内部按“快链 -> 慢链”顺序编排。
- 快链先把可预览模型写入 `model_assets`。
- 慢链完成后使用同一个 `scene_id` 再次 upsert `model_assets`，覆盖快链结果。
- 前端只展示一张场景卡片，体验上表现为“先可看、后变精”。

前端对接目标：

1. 视频任务默认使用 `task_type=video_dual_chain`。
2. 任务列表能展示双链任务、实时日志和失败原因。
3. Recall / 模型库能在快链完成后尽快看到模型，不必等慢链全部结束。
4. 同一 `scene_id` 只出现一张模型卡片，慢链完成后自动刷新为最终结果。
5. 不依赖尚未实现的 `phase` 或 `model_versions` 表，先兼容 V1 后端。

## 2. 当前实现审计结论

### 2.1 Supabase Edge Function

当前没有专门的 `video_dual_chain` Edge Function。视频任务主要由 Flutter 直接：

1. 上传视频到 Supabase Storage。
2. 插入 `processing_tasks`。
3. 等待 Python Worker 轮询并处理。

`confirm-text-image` Edge Function 只覆盖文生图确认后的单图任务，会创建 `single_image_sam3d` 或 `single_image_sharp`，不属于视频快慢双链入口。

结论：前端接入快慢双链时，短期仍走 Supabase SDK 直写任务表；生产化阶段建议新增统一任务创建 Edge Function，用服务端校验 `task_type`、`task_params`、`user_id` 和 Storage 路径。

### 2.2 Python 计算后端

当前双链核心在：

- `ai_engine/3dgs/src/core/worker.py`
  - `_process_task()` 中识别 `task_type == "video_dual_chain"`。
  - `_run_video_dual_chain()` 负责快链和慢链编排。
  - `_run_pipeline_once()` 负责单次 pipeline 执行、上传和 `model_assets` upsert。

双链参数：

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `slow_pipeline` | `video_3dgs` | 慢链 pipeline，可切换为 `da3_feed_forward_3dgs` |
| `sam3d_vram_threshold_gb` | `25` | 快链判定为 object 时，启用 SAM3D 的显存阈值 |
| `best_frame_sample_count` | `8` | 从视频中抽取候选帧数量，用于最佳帧选择 |
| `mapper_type` | 可选 | 慢链 `video_3dgs` 可透传给底层 pipeline |

结果写入策略：

- 快链输出写入 Storage：`{user_id}/{scene_id}/output/...`
- 快链 upsert `model_assets(scene_id)`。
- 慢链输出写入同一场景 output 路径。
- 慢链再次 upsert `model_assets(scene_id)`。

这意味着前端不能把快链和慢链当作两个模型处理；前端应把 `scene_id` 作为模型卡片稳定身份。

### 2.3 Flutter 前端

当前已有部分接入：

- `app/lib/pages/video_submit.dart` 已经默认提交 `video_dual_chain`。
- `app/lib/pages/generate.dart` 有 `video_dual_chain` 选项，但默认值仍是 `video_3dgs`。
- `app/lib/pages/generate/generate_submission.dart` 已能为 `video_dual_chain` 写入 `slow_pipeline`。
- `app/lib/pages/task_list/category_section.dart` 已支持 `Dual Chain` 标签和 `Icons.hub` 图标。
- `app/lib/pages/recall/recall_data_sync.dart` 已监听 `processing_tasks`，并读取 `logs`。
- `Recall` 模型列表从 `model_assets` 读取 `ply_path`、`preview_img_path`、`scene_id`。

关键缺口：

1. 视频默认入口未完全统一，Generate 页面仍默认 `video_3dgs`。
2. 快链完成时任务仍处于 `processing`，Recall 页面若只等任务完成才刷新，会错过“快链可预览”的体验。
3. 当前没有 `phase` 字段，前端需要从 `logs` 推导阶段。
4. `record.dart` 也创建 `video_dual_chain`，但只写 `image_count`，需要确认是否存在 `raw/video.mp4`，否则 Worker 下载视频会失败。

## 3. 数据契约

### 3.1 Storage 路径

视频双链任务必须满足：

```text
{user_id}/{scene_id}/raw/video.mp4
```

前端上传完成后再创建任务。若任务创建失败，应清理刚上传的视频，避免产生孤儿 Storage 文件。

输出由 Worker 写入：

```text
{user_id}/{scene_id}/output/point_cloud.ply
{user_id}/{scene_id}/output/point_cloud.splat
{user_id}/{scene_id}/output/preview.jpg
{user_id}/{scene_id}/output/webgl_poses.json
```

实际文件扩展名由 pipeline 和压缩配置决定，前端不要硬编码只支持 `.ply`。

### 3.2 processing_tasks

前端创建任务的推荐 payload：

```dart
await Supabase.instance.client.from('processing_tasks').insert({
  'scene_id': sceneId,
  'user_id': user.id,
  'display_name': displayName,
  'task_type': 'video_dual_chain',
  'task_params': {
    'slow_pipeline': 'video_3dgs',
    'sam3d_vram_threshold_gb': 25,
    'best_frame_sample_count': 8,
    'mapper_type': 'da3',
  },
  'status': 'pending',
});
```

字段要求：

| 字段 | 必填 | 说明 |
|---|---|---|
| `scene_id` | 是 | 前端生成，Storage 路径和模型卡片稳定 ID |
| `user_id` | 是 | 当前登录用户 ID |
| `display_name` | 否 | 用户输入的任务名，后续可回填模型展示名 |
| `task_type` | 是 | 固定为 `video_dual_chain` |
| `task_params` | 是 | 双链参数 |
| `status` | 是 | 创建时固定为 `pending` |

### 3.3 model_assets

前端读取模型时应以 `scene_id` 作为业务主键理解：

```dart
final models = await Supabase.instance.client
    .from('model_assets')
    .select('id, scene_id, user_id, display_name, description, objects, tags, ply_path, preview_img_path, meta_info, created_at')
    .eq('user_id', user.id)
    .order('created_at', ascending: false);
```

说明：

- `ply_path` 是 Storage 相对路径或历史完整 URL，读取后统一归一化。
- `preview_img_path` 同样需要兼容相对路径和完整 URL。
- 同一 `scene_id` 的快链结果会被慢链结果覆盖，不应额外渲染第二张卡片。

## 4. 前端状态模型

V1 后端没有显式 `phase` 字段，前端用 `processing_tasks.status + logs + model_assets 是否存在` 推导展示状态。

### 4.1 任务状态

| 后端状态 | 前端状态 | 展示建议 |
|---|---|---|
| `pending` | 排队中 | 显示等待 Worker 接单 |
| `processing` 且无双链关键日志 | 准备中 | 显示上传完成，正在下载资源或初始化 |
| `processing` 且出现候选帧/快链判定日志 | 快链生成中 | 显示正在生成快速预览 |
| `processing` 且出现快链完成日志 | 快链可预览，慢链精修中 | 显示“可先查看，仍在精修” |
| `processing` 且快链失败、慢链继续 | 快链失败，慢链生成中 | 显示降级提示，不标红整个任务 |
| `completed` | 已完成 | 显示最终模型 |
| `failed` | 失败 | 显示最后一条错误日志 |

### 4.2 日志关键词映射

建议先用宽松关键词匹配，兼容中文和 emoji 被编码异常的情况：

| 阶段 | 匹配关键词 |
|---|---|
| 抽帧 | `候选帧`、`extract`、`frame` |
| 快链判定 | `快链目标判定`、`scene/object`、`SHARP`、`SAM3D` |
| 快链完成 | `快链完成` |
| 快链失败 | `快链失败` |
| 慢链开始 | `慢链`、`video_3dgs`、`da3_feed_forward_3dgs` |
| 慢链完成 | `慢链完成` |
| 双链全失败 | `快慢双链均失败` |

示例工具函数：

```dart
enum DualChainPhase {
  queued,
  preparing,
  fastRunning,
  fastReadySlowRunning,
  fastFailedSlowRunning,
  completed,
  failed,
}

DualChainPhase inferDualChainPhase({
  required String status,
  required List<String> logs,
}) {
  final joined = logs.join('\n');

  if (status == 'completed') return DualChainPhase.completed;
  if (status == 'failed') return DualChainPhase.failed;
  if (status == 'pending') return DualChainPhase.queued;

  if (joined.contains('快链完成')) {
    return DualChainPhase.fastReadySlowRunning;
  }
  if (joined.contains('快链失败')) {
    return DualChainPhase.fastFailedSlowRunning;
  }
  if (joined.contains('快链目标判定') ||
      joined.contains('候选帧') ||
      joined.contains('SHARP') ||
      joined.contains('SAM3D')) {
    return DualChainPhase.fastRunning;
  }

  return DualChainPhase.preparing;
}
```

## 5. 页面对接方案

### 5.1 Generate 视频页

目标：所有普通视频上传默认走双链。

改造点：

1. 将 `_selectedVideoTaskType` 默认值从 `video_3dgs` 改为 `video_dual_chain`。
2. 视频提交成功后重置值也改为 `video_dual_chain`。
3. 保留高级任务类型选择入口，允许用户手动选择 `video_3dgs`、`da3_sugar`、`da3_2dgs` 等专项 pipeline。
4. `video_dual_chain` 的提示文案统一为“先生成快速预览，再自动精修”。

推荐默认参数：

```dart
case 'video_dual_chain':
  return {
    'slow_pipeline': 'video_3dgs',
    'sam3d_vram_threshold_gb': 25,
    'best_frame_sample_count': 8,
    'mapper_type': 'da3',
  };
```

### 5.2 VideoSubmit 独立页

当前已经提交 `video_dual_chain`，建议补齐：

1. 上传前显示任务模式为“视频双链”。
2. 上传成功后跳转任务列表或 Recall 页面时带上 `scene_id`。
3. 任务创建失败时清理 `raw/video.mp4`。
4. 把 `task_params` 构造抽到共享工具，避免 Generate 页和 VideoSubmit 页重复漂移。

### 5.3 TaskList

目标：任务列表不仅显示 `processing`，还显示双链阶段。

改造点：

1. 对 `task_type == 'video_dual_chain'` 使用 `inferDualChainPhase()`。
2. 卡片副标题显示最新日志。
3. 快链完成后显示一个“可预览”标识，但任务仍保留在 processing 分组。
4. 如果快链失败但慢链继续，不把整个任务标为失败。
5. `failed` 状态优先展示最后一条包含“失败”“Error”“Traceback”的日志。

展示建议：

| 阶段 | 标题 | 副文案 |
|---|---|---|
| `queued` | 排队中 | 等待计算节点接单 |
| `fastRunning` | 正在生成快速预览 | 选取关键帧并生成初版模型 |
| `fastReadySlowRunning` | 快速预览已可用 | 高质量版本仍在精修 |
| `fastFailedSlowRunning` | 快速预览未生成 | 已自动转入高质量重建 |
| `completed` | 已完成 | 最终模型已可查看 |
| `failed` | 生成失败 | 展示错误摘要 |

### 5.4 Recall / 模型库

目标：快链完成后尽快出现模型卡片，慢链完成后同卡刷新。

改造点：

1. 保持 `model_assets` 作为模型列表数据源。
2. 监听 `processing_tasks` 日志，当某个双链任务出现“快链完成”后，立即刷新 `model_assets`。
3. 可选增加 `model_assets` Realtime 监听，收到 INSERT / UPDATE 后只刷新对应 `scene_id`。
4. 模型卡片展示 `scene_id` 稳定身份，不根据 `id` 变化重复插入。
5. 如果任务仍在 `processing` 且 `model_assets` 已有同 `scene_id`，卡片加“精修中”状态。

推荐数据合并策略：

```text
processing_tasks(scene_id, status, logs, task_type)
        +
model_assets(scene_id, ply_path, preview_img_path, meta_info)
        =
ModelCard(sceneId, modelUrl, previewUrl, dualChainPhase)
```

不要把 `processing_tasks.id` 当作模型卡片 ID。任务 ID 只用于日志和状态；模型卡片以 `model_assets.scene_id` 为主。

### 5.5 WebGL Viewer

Viewer 不需要知道快慢链细节，只消费最新的 `ply_path`。

前端需要保证：

1. 打开模型前重新读取一次目标 `scene_id` 的 `model_assets`，避免使用慢链覆盖前的旧 URL。
2. `ply_path` 和 `preview_img_path` 都经过 Storage URL 归一化。
3. 若慢链覆盖发生在 Viewer 已打开期间，可提示“模型已更新”，由用户手动刷新当前模型；不要在用户操作中途强制替换 3D 场景。

## 6. Realtime 与刷新策略

推荐分两层：

### 6.1 processing_tasks 监听

用途：

- 展示任务状态。
- 展示日志。
- 推导双链阶段。
- 触发模型列表刷新。

触发刷新条件：

1. `status` 从 `pending` 变为 `processing`。
2. `logs` 新增包含“快链完成”。
3. `logs` 新增包含“慢链完成”。
4. `status` 变为 `completed` 或 `failed`。

### 6.2 model_assets 监听

用途：

- 快链 upsert 后立即出现模型卡片。
- 慢链 upsert 后刷新同一模型卡片。

实现方式：

```dart
final channel = Supabase.instance.client.channel('public:model_assets:recall');

channel.onPostgresChanges(
  event: PostgresChangeEvent.all,
  schema: 'public',
  table: 'model_assets',
  callback: (payload) {
    final sceneId = payload.newRecord['scene_id']?.toString();
    if (sceneId != null) {
      refreshModelBySceneId(sceneId);
    }
  },
).subscribe();
```

注意：如果生产环境启用 RLS，需要确保 Realtime 策略只允许用户收到自己的 `model_assets` 变更。

## 7. 错误处理

### 7.1 上传失败

前端处理：

1. 不创建 `processing_tasks`。
2. 显示上传失败原因。
3. 允许用户重试。

### 7.2 任务创建失败

前端处理：

1. 删除已上传的 `{user_id}/{scene_id}/raw/video.mp4`。
2. 显示“任务创建失败，请重试”。
3. 记录 debug 日志，包含 `scene_id` 和 Supabase 错误。

### 7.3 快链失败

后端策略是继续慢链。前端不应标记整个任务失败，应展示：

```text
快速预览未生成，已自动转入高质量重建。
```

### 7.4 慢链失败但快链成功

后端会让任务最终 `completed`。前端可从日志中识别“慢链失败”，并展示弱提示：

```text
已提供快速预览，高质量版本本次未完成。
```

### 7.5 快慢链均失败

任务 `status=failed`。前端展示最后错误摘要，并提供重新提交入口。

## 8. 兼容性与迁移

### 8.1 历史 `video_3dgs` 任务

历史任务保持原样，不迁移。TaskList 按 `task_type` 区分：

- `video_3dgs`：传统单链。
- `video_dual_chain`：双链阶段推导。

### 8.2 文生图和单图任务

不接入视频双链，仍按：

- `single_image_sam3d`
- `single_image_sharp`

处理。

### 8.3 流式拍摄入口

`record.dart` 当前创建 `video_dual_chain` 时只写 `image_count`。需要先确认该链路是否会生成并上传：

```text
{user_id}/{scene_id}/raw/video.mp4
```

如果没有，应选择其中一个方案：

1. 在前端或后端把流式图片合成为 `video.mp4` 后再创建 `video_dual_chain`。
2. 新增 Worker 输入分支，允许 `video_dual_chain` 从 raw 图片序列生成候选帧和慢链输入。
3. 暂时把流式拍摄任务改回已有可用的任务类型，避免进入必然失败路径。

## 9. 建议落地顺序

### 第一阶段：不改库表的 V1 前端闭环

1. Generate 视频默认任务改为 `video_dual_chain`。
2. 抽出统一 `buildVideoTaskParams(taskType)`。
3. TaskList 增加双链阶段推导和展示。
4. Recall 在“快链完成”日志出现时刷新 `model_assets`。
5. 模型卡片增加“精修中”弱状态。
6. 修正或隔离 `record.dart` 的视频输入契约风险。

### 第二阶段：增强实时体验

1. Recall 增加 `model_assets` Realtime 监听。
2. Viewer 打开前按 `scene_id` 重新拉取最新模型路径。
3. 慢链覆盖时提示用户刷新当前查看器。
4. 对失败日志做更稳定的摘要提取。

### 第三阶段：生产化收敛

1. 新增 `create-processing-task` Edge Function。
2. 前端不再直接写 `processing_tasks`。
3. 数据库增加 `task_phase` 或 `phase` 字段，替代日志关键词推导。
4. 增加 `model_versions` 表，支持 fast / slow 版本切换。
5. 收紧 `processing_tasks` 和 `model_assets` RLS。

## 10. 测试方案

### 10.1 Flutter 单元测试

建议覆盖：

1. `inferDualChainPhase()` 对不同日志组合的阶段推导。
2. `buildVideoTaskParams('video_dual_chain')` 返回默认参数。
3. Storage URL 归一化兼容相对路径和完整 URL。
4. `scene_id` 相同的模型更新不会生成重复卡片。

### 10.2 Flutter 集成测试

建议覆盖：

1. 上传视频后创建 `video_dual_chain` 任务。
2. 任务列表显示 `Dual Chain`。
3. 模拟日志出现“快链完成”后 Recall 触发刷新。
4. 模拟 `model_assets` upsert 后同一模型卡片更新。
5. 任务 `completed` 后模型可打开 Viewer。

### 10.3 后端联调测试

使用测试视频提交真实任务，观察：

1. `processing_tasks.status` 从 `pending` 到 `processing`。
2. `logs` 出现候选帧、快链判定、快链完成、慢链完成。
3. 快链完成后 `model_assets` 已有同 `scene_id` 记录。
4. 慢链完成后同 `scene_id` 的 `ply_path` 或 `preview_img_path` 被更新。
5. `processing_tasks.status` 最终为 `completed`。

## 11. 验收标准

功能验收：

1. 从视频入口提交任务时，默认创建 `video_dual_chain`。
2. 任务列表能看到双链阶段，而不是只有泛化的 processing。
3. 快链完成后，Recall 能看到可打开的模型卡片。
4. 慢链完成后，同一模型卡片刷新为最终结果，不新增第二张卡片。
5. 快链失败但慢链继续时，前端不误报整体失败。
6. 快慢链均失败时，前端展示明确失败原因。

工程验收：

1. 新增阶段推导逻辑有单元测试。
2. Generate 和 VideoSubmit 共用任务参数构造逻辑。
3. 不引入新的硬编码用户 ID、密钥或 Storage 根路径。
4. 不破坏历史 `video_3dgs`、单图和文生图任务。

## 12. 后续演进建议

V1 前端应优先用现有 `logs` 和 `model_assets(scene_id)` 形成闭环，不急于新增库表。

当双链体验稳定后，再推进：

1. `processing_tasks.phase`：后端显式写入 `fast_running`、`fast_ready`、`slow_running`、`completed`。
2. `model_versions`：保留 fast / slow 两个版本，支持用户切换、对比和回退。
3. 统一任务创建 Edge Function：收敛权限、参数校验和 Storage 路径校验。
4. Dashboard 增加双链阶段和 fast / slow 耗时统计。
