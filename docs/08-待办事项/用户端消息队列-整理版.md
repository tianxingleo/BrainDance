# 用户端消息队列与状态管理方案

## 概述

要实现类似百度网盘的体验（上传 -> 等待/转码中 -> 完成/可预览），同时又要保证服务器不被打挂，核心秘诀在于：

**不要"轮询" (Polling)，要"监听" (Listening)。**

---

## 1. 核心架构：如何避免持续扫描

如果 1000 个用户每秒都问一次服务器"我好了吗？"，数据库确实会崩。

**解决方案：Supabase Realtime (WebSocket 推送)**

- **传统做法 (错误)**：前端写个 `setInterval`，每 3 秒发一个 HTTP 请求查状态。
- **推荐做法 (正确)**：前端建立一个长连接 (WebSocket) 监听数据库。
- 当后端 Worker 把任务状态从 `pending` 改为 `processing` 再改为 `completed` 时，数据库会**主动**给前端发一个信号。
- 前端收到信号，局部刷新 UI。
- **服务器压力**：极小。PostgreSQL 的 Realtime 机制非常高效。

---

## 2. 数据源设计

**答案：查 `processing_tasks` 表（流水线表）。**

- **不要每个用户建表**：这是数据库设计的禁忌。100万用户建100万张表，数据库维护会极其困难。
- **不要查向量库 (`model_assets`)**：向量库只存"成功的、用来被搜索"的数据。它不存"排队中"或"失败"的状态，做不了进度条。

**正确设计：**

所有用户共用一张 `processing_tasks` 表，通过 `user_id` 和 **RLS (行级安全)** 逻辑上隔离。用户 A 查这张表，只能看到用户 A 的数据，感觉上就像"由于我有自己的表"。

---

## 3. 前端逻辑：如何实现灰色加载效果

前端（Flutter）需要维护一个**统一的数据列表**，这个列表的数据来源是**混合**的。

#### 逻辑流程：

1. **初始加载**：用户打开页面，拉取最近 20 条记录。
2. **渲染 UI**：根据 `status` 字段决定样式。
   - `pending` (排队): **灰色卡片** + 显示"等待中..."
   - `processing` (生成中): **灰色卡片** + 显示"转圈圈/进度条"
   - `completed` (完成): **彩色卡片** + 显示预览图 + 点击可查看
   - `failed` (失败): **红色卡片** + 显示"重试"

3. **实时更新**：一旦收到 Realtime 推送（比如某条任务变 `completed` 了），**就地**把那个灰色卡片替换成彩色卡片。

---

## 4. 代码实现方案 (Flutter)

这是如何实现"百度网盘"效果的核心代码。

```dart
// 前端数据模型
class TaskItem {
  final String id;
  final String status; // pending, processing, completed, failed
  final String? plyPath; // 只有 completed 才有
  // ... 其他字段
}

// 界面组件
class MyNetDiskPage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    // 使用 StreamBuilder 监听 Supabase 的实时数据流
    return StreamBuilder<List<Map<String, dynamic>>>(
      stream: Supabase.instance.client
          .from('processing_tasks')
          .stream(primaryKey: ['id']) // 监听主键
          .eq('user_id', myUserId)    // 只监听我的数据
          .order('created_at', ascending: false), // 最新的在上面
          
      builder: (context, snapshot) {
        if (!snapshot.hasData) return LoadingSkeleton(); // 骨架屏

        final tasks = snapshot.data!;
        
        return GridView.builder(
          gridDelegate: SliverGridDelegateWithFixedCrossAxisCount(crossAxisCount: 2),
          itemCount: tasks.length,
          itemBuilder: (context, index) {
            final task = tasks[index];
            final status = task['status'];
            
            // 核心 UI 逻辑：根据状态分发样式
            if (status == 'completed') {
              return _buildSuccessCard(task); // 彩色，可点击
            } else if (status == 'failed') {
              return _buildErrorCard(task);   // 红色，报错
            } else {
              // pending 或 processing
              return _buildLoadingCard(task); // 灰色，带加载动画
            }
          },
        );
      },
    );
  }

  // 灰色加载卡片 (百度网盘的占位效果)
  Widget _buildLoadingCard(Map task) {
    return Card(
      color: Colors.grey[200], // 灰色背景
      child: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            CircularProgressIndicator(), // 转圈圈
            SizedBox(height: 10),
            Text(
              task['status'] == 'pending' ? "排队中..." : "AI生成中...",
              style: TextStyle(color: Colors.grey),
            )
          ],
        ),
      ),
    );
  }

  // 成功卡片
  Widget _buildSuccessCard(Map task) {
    // 拼接下载链接
    final url = "https://<PROJECT>.supabase.co/storage/.../${task['ply_path']}";
    return Card(
      child: InkWell(
        onTap: () => open3DViewer(url),
        child: Column(
          children: [
            Image.network(thumbnailUrl), // 预览图
            Text("模型生成成功"),
          ],
        ),
      ),
    );
  }
}
```

## 5. 已渲染成功的数据获取

获取的数据分两部分：

1. **元数据 (Metadata)**：
   - **来源**：`processing_tasks` 表中的 `logs` (里面有标签)、`quality_score` (评分)、`status`。
   - **获取方式**：上面的 `StreamBuilder` 已经自动拿到了。

2. **实体文件 (File)**：
   - **来源**：Supabase Storage。
   - **获取方式**：
     Worker 跑完后，会把文件路径更新到数据库字段 `ply_path`（例如 `user_123/scene_001/output/point_cloud.ply`）。
     前端拿到这个路径，拼接上项目 的 **Storage Public URL** 前缀，就得到了下载链接。

---

## 6. 本地缓存策略

**建议：做轻量级缓存，但不要过度设计。**

- **为什么要做？** 用户杀掉 App 再打开，如果不缓存，屏幕会白屏闪烁一下才能加载出列表。
- **怎么做？**
  - **简单版**：Flutter 的 `cached_network_image` 插件会自动缓存预览图。这就够了。
  - **进阶版**：使用 `hive` 或 `shared_preferences` 把 `processing_tasks` 的 JSON 数据存一份在本地。每次打开 App，先从本地读并显示（秒开），同时后台悄悄连 Supabase 更新数据。
- **不要做**：不要自己写复杂的 SQLite 同步逻辑，除非 App 需要完全离线使用。对于网盘类应用，"联网才能看"是用户默认接受的。

---

## 7. 总结方案

1. **表结构**：单表 `processing_tasks` + RLS 隔离。
2. **通信机制**：**Supabase Realtime Stream** (彻底替代轮询，解决服务器压力)。
3. **UI 策略**：数据驱动 UI。`status != completed` 就显示灰色 Loading 态。
4. **文件获取**：数据库存 Path -> 前端拼 URL -> 3D 引擎加载。

这样，既拥有了百度网盘般的实时进度体验，又不需要担心服务器负载爆炸。

## 补充：离线推送与灵动岛实现

**Supabase Realtime (WebSocket) 只有在前端 App 存活（前台或后台保活）时才有效。** 如果用户把 App 杀掉了，WebSocket 就会断开，前端也就收不到"任务完成"的信号了。

要实现 **"灵动岛 (Dynamic Island) / 实况窗 (Live Activities)"** 或者 **"离线推送"**，需要引入 **"服务端推送通知 (Push Notifications)"** 机制。

对于 BrainDance 这种架构，最优雅的方案是：**Python Worker 只管改数据库，由 Supabase 的 Edge Function (边缘函数) 负责触发推送。**

---

### 1. 核心架构：从拉到推

需要增加一条新的链路：

1. **App 在线时**：走 Realtime (WebSocket) -> 实时进度条。
2. **App 离线/锁屏时**：走 **APNs (Apple) / FCM (Google)** -> 灵动岛/通知栏。

**架构图：**

```mermaid
graph TD
    User[用户] -->|上传视频| DB[(Supabase DB)]
    Worker[Python Worker] -->|1. 监听任务| DB
    Worker -->|2. 更新状态: processing| DB
    
    %% 实时链路
    DB -.->|3a. Realtime (WebSocket)| App[Flutter App (前台)]
    
    %% 推送链路 (新增)
    DB -->|3b. Webhook 触发| Edge[Supabase Edge Function]
    Edge -->|4. 调用苹果/谷歌接口| APNs[APNs / FCM]
    APNs -->|5. 更新灵动岛/通知| Phone[用户手机 (锁屏/灵动岛)]
```

---

### 2. 数据库改造：记住通知发给谁

Worker 修改任务状态时，并不知道这个任务属于哪台手机。所以需要在数据库里存一下用户的 **Push Token**（推送令牌）。

**SQL 修改 (Supabase):**

需要一张新表（或者加在 `auth.users` 的扩展表里）来存用户的设备 Token。

```sql
-- 创建设备表，记录用户的推送 Token
create table public.user_devices (
  user_id uuid references auth.users not null,
  fcm_token text,           -- Android/常规通知 Token
  apns_token text,          -- iOS 灵动岛专用 Token (Live Activity Token)
  primary key (user_id, fcm_token)
);

-- 开启 RLS，允许用户写入自己的 Token
alter table public.user_devices enable row level security;
create policy "Users can upload their device tokens"
on public.user_devices for insert
with check ( auth.uid() = user_id );
```

---

### 3. 实现灵动岛 (Live Activities) 的流程

灵动岛本质上是一个 **"临时存在的锁屏挂件"**。它的更新机制很特殊，需要使用 **Token Update**。

#### 第一步：Flutter 端 (启动灵动岛)

当用户点击"上传视频"后，App 需要立刻在本地启动一个灵动岛 Activity。

**插件推荐**: `live_activities` (Flutter pub)

```dart
// Flutter 代码示例
import 'package:live_activities/live_activities.dart';

// 1. 在上传开始时，启动灵动岛
final activityId = await _liveActivitiesPlugin.createActivity(
  attributes: {
    'scene_id': 'scene_001',
    'total_files': 10,
  },
  contentState: {
    'progress': 0,
    'status': '上传完成，排队中...',
  },
  pushToken: true, // 关键：请求系统给一个专门更新这个岛的 Token
);

// 2. 拿到 Token 后，存到 Supabase，和当前任务绑定！
_liveActivitiesPlugin.activityUpdateStream.listen((event) {
  final pushToken = event.pushToken;
  // 将 pushToken 和 taskId 存入数据库
  // 这样后端才知道更新哪个岛
  supabase.from('task_activities').insert({
    'task_id': taskId,
    'push_token': pushToken 
  });
});
```

#### 第二步：Supabase Edge Function (负责发通知)

**千万不要在 Python Worker 里写推送逻辑。** Worker 应该只专注算 3DGS。推送逻辑应该放在 Supabase 的 **Database Webhook** 里。

**逻辑：**

每当 `processing_tasks` 表的 `status` 变了 -> 触发 Webhook -> 运行 Edge Function -> 发送请求给苹果。

**Edge Function (TypeScript) 伪代码：**

```typescript
// supabase/functions/push-notify/index.ts

serve(async (req) => {
  const payload = await req.json();
  const { record } = payload; // 拿到数据库变更的那一行 (status='completed')

  // 1. 查找这个任务对应的 灵动岛 Token
  const { data: activity } = await supabase
    .from('task_activities')
    .select('push_token')
    .eq('task_id', record.id)
    .single();

  if (activity && activity.push_token) {
    // 2. 构造灵动岛更新 Payload (苹果规定格式)
    const apnsPayload = {
      "aps": {
        "timestamp": Date.now() / 1000,
        "event": "update",
        "content-state": {
          "status": record.status, // processing, completed
          "progress": record.status === 'completed' ? 100 : 50
        },
        "alert": {
          "title": "3DGS 生成进度",
          "body": record.status === 'completed' ? "渲染完成！点击查看" : "正在生成中..."
        }
      }
    };

    // 3. 发送给苹果 APNs
    await sendToApple(activity.push_token, apnsPayload);
  }
});
```

#### 第三步：配置 Database Webhook

在 Supabase 网页控制台：

1. 进入 **Database** -> **Webhooks**。
2. 新建 Webhook：
   - **Table**: `processing_tasks`
   - **Events**: `UPDATE` (当记录更新时)
   - **HTTP Request**: POST 到 Edge Function URL。

---

### 4. 最终效果体验

1. **用户上传**：
   - App 界面显示上传进度。
   - 同时，**iPhone 顶部灵动岛弹出**，显示"BrainDance: 排队中..."。
   - 即使用户**杀掉 App**，灵动岛依然停留在顶部。

2. **Worker 开始工作**：
   - Worker 把 DB 状态改为 `processing`。
   - DB 触发 Webhook -> Edge Function。
   - Edge Function 发推送。
   - **用户的灵动岛跳动一下**，文字变为"BrainDance: AI 生成中..."，进度圈转动。

3. **Worker 完成工作**：
   - Worker 把 DB 状态改为 `completed`。
   - DB 触发 Webhook。
   - **灵动岛变绿**，显示"✅ 生成完成"。
   - 同时手机收到一条横幅通知："您的 10 个模型已全部生成完毕"。

---

### 5. 总结

要实现这个功能，不需要改 Python Worker 的核心代码，只需要做"外围建设"：

1. **Flutter 端**：接入 `live_activities` 插件，创建 Activity 并把 Token 传给后端。
2. **Supabase 端**：
   - 建表存 Token。
   - 写一个 Edge Function (TypeScript) 用来调苹果/谷歌的推送接口。
   - 配置 Webhook，让数据库变动自动触发函数。

这样，Worker 依然只负责单纯的计算，而"用户体验"的部分则由 Supabase 和 Flutter 完美配合完成。这是最解耦、最健壮的方案。
