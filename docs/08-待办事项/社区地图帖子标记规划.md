# 社区地图帖子标记规划（2026-05-21）

## 1. 现状

当前 Flutter 社区页已经有地图入口与地图页：

- `app/lib/pages/community.dart` 负责切换探索页、发现页、投稿页，并打开地图页。
- `app/lib/pages/community/map_page.dart` 已接入 `flutter_map`，但目前只渲染底图和缩放控件，没有帖子标记层。
- `app/lib/pages/community/repository.dart` 已能从 `community_posts` 读取 `latitude / longitude / place_name / title` 等字段。
- 数据库侧 `community_posts` 已具备地理字段与索引，`docs/03-API参考/数据库设计.md` 也已说明该表用于“社区贴文流与地图探索”。

结论：这次不是补建地图能力，而是在现有地图上补“帖子标记 + 数量控制 + 稳定分布”。

## 2. 目标

1. 在地图上按帖子经纬度显示标记。
2. 允许用户设置最大标记显示数。
3. 标记的空间分布规则不随缩放级别变化。
4. 标记点击后可进入帖子详情或地点聚合页。

## 3. 约束

- 不能用“按像素半径聚类”的方式做主逻辑，因为那会随着缩放改变分布。
- 不能把 marker 选择绑定到 zoom 级别的重采样结果。
- 不能直接复用当前 `fetchPosts()` 的 24 条 feed 限制作为地图数据源，地图需要独立的数据读取路径。

## 4. 方案

### 4.1 数据层

新增一条专用于地图的读取路径，例如：

- `fetchMapPosts({ limit, onlyPublic })`
- 或 `fetchCommunityMarkers()`

返回字段只保留地图必需内容：

- `id`
- `title`
- `place_name`
- `latitude`
- `longitude`
- `cover_image_url`
- `created_at`
- `like_count / view_count` 等可选元信息

地图页不依赖完整 feed 卡片数据，先把标记渲染需要的字段拿齐即可。

### 4.2 标记选择策略

采用“固定地理网格 + 密度配额 + 稳定排序 + 数量上限”的策略：

1. 将帖子按固定地理网格分桶，优先使用 geohash 或等价的固定空间单元。
2. 统计每个桶的帖子数量，用它计算该桶应拿到的展示配额，确保高密度区域拿到更多名额。
3. 每个桶内再按固定规则选代表标记：
   - 优先最近更新或最新发布
   - 再按互动量或权重
   - 最后按 `id` 保持稳定性
4. 当分配后的代表总数仍超过用户设置的最大值时，再做一次稳定裁剪。

这里的关键不是“网格本身等于密度”，而是“网格负责稳定，配额负责密度”。这样既能保持缩放前后分布不乱跳，也能让高密度地区在有限名额里更有存在感。

### 4.3 用户可控的最大标记数

在社区地图页增加一个“最大标记数”设置入口，建议放在：

- 地图页右上角的设置按钮
- 或底部抽屉里的滑块 / 步进器

建议提供预设档位：

- 20
- 50
- 100
- 自定义

配置建议本地持久化，避免每次进页都重设。

### 4.4 地图渲染层

在 `CommunityMapPage` 和 `CommunityAmapPreview` 之间抽一个共享的 marker 层组件，避免预览页和全屏页逻辑分叉。

渲染层职责：

- 接收帖子标记列表
- 生成 `MarkerLayer`
- 处理点击事件
- 在必要时显示简化计数徽标或地点名

如果后续标记数量继续增长，可再升级为服务端预聚合，但第一版先在 Flutter 端完成闭环。

## 5. 交互

- 点标记：进入帖子详情页。
- 长按标记：展开同地点帖子列表，复用现有地点聚合逻辑。
- 调整最大标记数：立即刷新当前地图标记，不重建底图。
- 缩放地图：只改变视图范围，不改变选点规则。

## 6. 实施拆分

1. 补地图数据读取接口。
2. 抽取共享 marker 层组件。
3. 增加最大标记数设置控件与本地持久化。
4. 接入详情跳转与地点聚合入口。
5. 做一次性能检查，确认标记数量上限生效且缩放不触发重新洗牌。

## 7. 验收标准

- 地图页能显示帖子标记。
- 标记位置与 `community_posts.latitude / longitude` 一致。
- 用户可设置最大标记数并生效。
- 同一批数据在不同缩放级别下不会因为 zoom 重新聚类。
- 标记数量受上限约束，页面在常见数据量下不卡顿。

## 8. 风险

- 如果帖子规模上升到很大，纯 Flutter 客户端筛选会有性能压力。
- 如果后续需要“按当前可见区域实时刷新”，必须继续保持“固定地理网格”这个前提，不能退回到按像素聚合。
- 如果地图页面要显示过多附属信息，marker 点击层会变重，需要把详情内容延迟加载。
