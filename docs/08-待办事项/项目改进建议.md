# BrainDance 项目改进建议 (2026-01-20)

以下建议分门别类，优先级按重要性排序（工程问题优先、然后基础设施、AI 能力、最后为产品/体验改善）。本文档仅做建议清单，所有实现应通过小步提交 + CI 验证。

## 1. 代码重构与工程化 (Engineering & Refactoring)

### 1.1 核心 Pipeline 统一化
- 统一入口：将所有重建逻辑收敛到 `ai_engine/3dgs/src/pipelines/` 下，消除散落在 demo 或 scripts 的重复调用。
- 接口标准化：定义 Pipeline 协议：`run(input_path: str, params: dict) -> (ply_path: str, metadata: dict)`。

### 1.2 增强异常处理与重试机制
- 对可重试的外部错误（网络、存储超时、模型下载失败）引入重试策略与 `retry_count` 字段。
- 将关键步骤（下载、训练、上传、写入 DB）用幂等操作封装，避免重复执行副作用。

### 1.3 自动化测试
- 增加单元测试与集成测试（mock Supabase、模拟上传/下载），并在 CI 中运行轻量级 E2E。


## 2. 后端架构优化 (Infrastructure & Scaling)

### 2.1 数据库性能优化
- 为 `processing_tasks` 添加联合索引 `(status, created_at)` 来优化轮询查询。
- 使用 `FOR UPDATE SKIP LOCKED` 或 RPC 封装的抢占逻辑，避免多实例竞争导致重复处理。
- 考虑在高并发场景下把热表切分成 TTL 分区或使用 `pg_partman` 以便归档历史任务。

### 2.2 存储管理优化
- 对生成的 PLY 模型实施存储生命周期策略（压缩、分层存储、删除长期无访问的中间产物）。


## 3. AI 与 RAG 深度增强 (AI & Spatial RAG)

### 3.1 增强空间语义理解
- 在 RAG 向量化文本中注入空间元数据（例如“床在窗左侧 2m”）以支持更精细的空间查询。

### 3.2 AI 质检系统升级
- 建立失败分析闭环：收集失败案例，自动分类（模糊/运动模糊/遮挡）并向用户提供拍摄建议。


## 4. 端到端功能闭环 (End-to-End Loop)

### 4.1 Edge Functions 落地
- 补齐 `supabase/functions/search/`，把向量匹配在边缘函数中暴露给前端，减少前端直接暴露 Keys 的需要。

### 4.2 前端渲染优化
- 探索移动端高效高斯泼溅渲染（WebGL/Metal）或服务端预烘焙缩略图以减轻移动端解码压力。
